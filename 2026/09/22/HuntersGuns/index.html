HuntersGuns

本来想谈一些代码，编程，项目相关的话题，但是想到之前的我一直都在谈论这些，在 AI 浪潮下，以及对于劳动和价值的思考，我决定将其另起一篇选读（暂时先欠下，最近还有竞赛项目，而且关于代码还有不少想写的）。

关于 Hunter’s Guns

OK，来谈两个方面，首先是我们的组。

我们组呈现出一种自由发展的模样（不自由的例子，有的组的指导老师是不允许组员切换方向的），在我这里尤甚（我出于兴趣尝试过不少方向），因此有一种开放的氛围。

组员以自我成长为核心（只要自己能有所进展就好，不拘泥于代码与项目），逐渐产出项目（最好是兴趣驱动）。这就是我们组的灵魂，实用主义，而非形式主义，只要你有所获即可。

组里的灵魂：hunter qi

灵魂当然是我们的指导老师，hunter qi。

在我眼中，hunter qi 是一个愿意倾听学生意见（我之前见过让我不要说其他的事情的老师，而和 hunter qi 可以谈天说地），并且给出属于你的立场的意见（也即十分真诚），而且不有效（因为其中有着 hunter qi 自己的思考）。

一次难忘的合作经历

之前有幸曾和 hunter qi 有过一次合作开发的经历，两人坐在一起解决 Bug，互相激励。项目有所进展之后，我们一起出去吃饭，休息，再各自分离。我看来，这是一次弥足珍贵的体验，这还是我头一次感到与别人合作是如此美妙。

这也是这次组 Repo 的一个很大的灵感。

关于 HuntersGunsRepo

其次是这个代表我们组的 Repo，宏大的车轱辘话我就不当复读机了，来点实打实的好处。

用最少的力气完成最大的项目：分工与协作

最近我的项目开发逐渐采用了这种方式，一个项目中的许多功能由组员来完成，我只要 Review 一眼 Pr，再跑一次测试，全绿，就可以合并进来，顺利地成为项目成长的力量。

这在以前是难以想象的，以前的组员在合作上只能负责代码之外的创意，文档，素材，视频，但是现在却可以参与到接口层面。每个人分工之后，每个人出一点力，不是很累，但是卓有成效，积累下来，项目最后便蔚为大观。

PS：之前隔壁组的组员想要在组内推行 Git 管理以及 Github 协作，但是其他组员说太过复杂，就此作废，这件事给我以及我们一个启示：要听别人给出的可以执行的意见，尤其是已经给出一个方案。

接下来的安排

  • 安装自己的 Agent，帮助自己剩下许多宝贵的精力，并且可以将自己的流程转化为文字，让 AI 执行。
  • 对组内有见解以及意见可以提 Issue，其实更为重要的是，有什么想要和组内成员沟通的（比如说有一个很好的创意），写好足够吸引人的开头，自然会有人给你提 Pr（至少我会给你出一把力）。
  • 以后大家的工作，首先是大家的兴趣，其次是目前组里积攒下的项目的优化（我有时候觉得给既有项目添加新功能更有成就感），我也会尽量把我之前的项目开放出一些可以替换的接口，方便大家练手。
